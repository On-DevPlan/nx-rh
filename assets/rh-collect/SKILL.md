# rh-collect — 把 git 仓库收进 nx-rh

## 这个 skill 解决什么

`nx-rh` 维护一份**本机仓库登记表**（路径 + 名称 + 描述 + 标签 + 备注），
让「这台机器上有哪些仓库、各自是干什么的」有地方可查，而不是每次重新翻盘。

本 skill 只做一件事：**发现 git 仓库 → 问过用户 → 写进登记表**。

## 铁律：先问再入

**任何写操作之前，先把「发现了什么、准备登记什么」摆给用户看，等他确认。**

登记表是用户的资产。agent 自作主张塞进去的条目，用户不知道它从哪来、
也不知道该不该留，过一阵就变成没人敢删的垃圾。所以：

- ❌ 不要「发现即登记」
- ✅ 先跑**只发现**模式 → 列给用户 → 他说收哪些才收

## 两种情况

### A. 你（agent）刚产出了仓库

你克隆了一个仓库、或在空目录 `git init` 之后，顺手问一句：

> 这个仓库要不要登记进 nx-rh？（`D:\code\my-proj`）
> 描述我先写成「xxx 的 yyy」，不对的话你给一句。

用户同意后：

```bash
nx-rh repo add <绝对路径> --desc "一句话说明它是干什么的" --tags "标签,标签"
```

`--desc` 是这条记录里最有价值的部分——**名字和路径自己会说话，描述不会**。
写不出描述时问用户，不要留空。

### B. 批量发现（扫一个目录）

```bash
nx-rh repo scan <目录> --dry-run              # 只列出，零副作用
nx-rh repo scan <目录> --dry-run --depth 4    # 往下找四层（默认 3）
nx-rh repo scan --dry-run                     # 目录留空 = 当前目录
```

输出会标出每个仓库**是否已经登记**：

```
发现（未登记） D:\code: 3 个 git 仓库
  已登记  D:\code\my-proj  (my-proj)
  未登记  D:\code\toy-1
  未登记  D:\code\toy-2
```

把「未登记」的列给用户，让他挑（也可以按他的意图先筛一遍再给）——
**不要直接把 12 个全登记**。挑完逐个 `repo add`，这样才能一条条写描述。

只有在用户明确说了「都收进来」时，才用不带 `--dry-run` 的那个：

```bash
nx-rh repo scan <目录>        # 会真的全部登记，desc 为空 —— 之后还得补
```

## 命令速查

| 命令 | 用途 |
| --- | --- |
| `nx-rh repo list` | 当前登记表 |
| `nx-rh repo get <id\|路径>` | 单条详情（id 与绝对路径都能定位） |
| `nx-rh repo scan [目录] --dry-run [--depth n]` | **只发现**，不登记 |
| `nx-rh repo scan [目录] [--depth n]` | 发现并全部登记（desc 为空） |
| `nx-rh repo add <路径> --desc "…" [--tags a,b] [--notes "…"]` | 登记一条 |
| `nx-rh repo update <id\|路径> --desc "…"` | 补 / 改描述 |
| `nx-rh repo remove <id>` | 移除登记（**不动磁盘文件**） |

面板上有同样的入口（「仓库」页）：`repo scan` 的「只发现」与「扫描登记」是两个独立按钮。

## 反例

| 做法 | 为什么坏 |
| --- | --- |
| 发现即登记、不告诉用户 | 登记表里冒出用户没见过的条目，他不敢删（怕是别处依赖的） |
| 批量扫描直接登记 12 个 | 12 条 `desc` 全空的记录 = 12 条没有信息量的噪音 |
| 登记时把 desc 留空 | 描述是这份表**唯一**推不出来的信息，空的等于没记 |
| 以为 `repo remove` 会删目录 | 它只移除登记；删文件是另一件事，必须明确告知用户 |
