# 08 · 远程订阅管理升级（对齐 vercel-labs/skills）

> 目标：把「远程订阅」从「能导入能更新」升级成**完整的外部 skill 管理面**——
> 搜索 → 导入 → 装到平台 → **检查版本** → 更新 → 增删改查；
> 并把总览页的噪音清掉，让远程订阅成为一等的可见区块。
>
> 参照实现：[vercel-labs/skills](https://github.com/vercel-labs/skills)（MIT，本机已 clone 在
> `D:\a_other\nxkvrepo\skills`）。移植的是**机制**（版本判定、导入/安装分工），
> 不是它的适配器表（79 个 agent）——本仓库自己的 `ADAPTERS` 表不动。

## 二、后端

### 1. 新增 `src/modules/skills/svc/version.js`（本次核心）

**判定精度：目录级。** 移植自 vercel-labs `src/git.ts:getGitTreeHash` +
`src/blob.ts:getSkillFolderHashFromTree`——两者算的是**同一个值**（git 树对象 SHA），
所以 GitHub API 路径与 clone 路径的结论完全可比。

判定流程（每个唯一 spec 只查一次，同源多 skill 共享结果）：

```
git 源：
  ① git ls-remote <url> <ref>  → 上游 commit
  ② commit === 台账缓存的 commit  → 该源全部 skill 判「最新」，不克隆（快路径）
  ③ commit 变了 → 拉一份（浅克隆到 staging）
       定位：台账 repoPath → 否则到上游重新发现（frontmatter name → 原目录名）
       算指纹：git rev-parse HEAD:<目录>  → 40 位 tree SHA
  ④ 与台账 folderHash 比 → 最新 / 待更新

download 源（归档 / 单文件）：
  重新下载 → skillDirHash（内容 md5）→ 与台账 hash 比
```

**状态取值**：`up-to-date` / `outdated` / `removed` / `unknown` / `skipped` / `error`。

`removed` 与 `unknown` 的区分（实测踩出来的坑）：

- 上游**完整扫过**却找不到 → `removed`（上游真删了）
- 只按台账路径查、路径又对不上 → `unknown`（可能挪了位置，不能说删了）

**check 只读不换盘**——与 `updateRemote`（边检查边换实体）严格分工。
这正是 `plan/07` R2 判定「待更新徽标 / 检查更新按钮」建立在不存在的能力上的那个缺口。

### 2. 台账扩展（`src/core/store.js`）

`remoteRepo` 从 `{ dir, skills }` 扩到 `{ dir, skills, commits, lastCheck }`：

| 字段 | 含义 |
| --- | --- |
| `skills[name].hash` | **本地副本**指纹（md5）→ 决定要不要换盘 |
| `skills[name].folderHash` | **上游目录**指纹（tree SHA）→ 决定上游有没有变 |
| `skills[name].repoPath` | 仓库内相对 SKILL.md 的路径 → 版本检查靠它定位 |
| `skills[name].skillPath` | 上游原目录名 → 上游改 frontmatter name 时的重定位依据（原有） |
| `commits[spec]` | 各上游最近一次已知 commit → ls-remote 快路径的基准 |
| `lastCheck` | 上次检查结论摘要 → 面板徽标读它，不必每次联网 |

老 store 不需要迁移（`normalize()` 补空对象即可）。

### 3. `svc/remote-repo.js` 改造

- `importToRemote`：clone 之后从 staging 直接算 tree SHA + commit 写台账
  （**不克隆第二份**——第一版实现克隆了两次，后来改为从 staging 算）
- `updateRemote`：换盘后同步刷新 `folderHash` / `repoPath`；内容没变但路径挪了也刷新
- **新增 `installFromRemote`**：导入 + 装到平台目录一条龙（对标 `skills add`）
- **删除** `linkIntoRemote` / `linkFromRemote`

### 4. `svc/sources.js`：远程 hub 默认登记

`ensureRemote()` 幂等且便宜（已登记就直接返回，不 mkdir 不写盘），`listSources()` 每次读
订阅源清单都调它 → 远程 hub **一开始就出现在订阅源列表里**（恒排末位），用户不必先「订阅」。

连带修：`svc/queries.js` 的 `hubProblemsFor()` 的 **empty 判定跳过远程源**——
远程 hub 是托管容器，初始为空是正常态，不该被 `skill hub check` 报成「空源」问题。

### 5. action 声明（`actions.remote.js`）

| 动作 | CLI | HTTP |
| --- | --- | --- |
| **删** | `skill hub remote link` | `POST /api/skills/remote/link` |
| **删** | `skill hub remote link-out` | `POST /api/skills/remote/link-out` |
| **增** | `skill hub remote check [name...]` | `GET /api/skills/remote/check` |
| **增** | `skill hub remote install <spec>` | `POST /api/skills/remote/install` |

### 7b. 「按地址安装」区段（补做）

用户指出：参考实现的 `skills add <package>` 本质是**贴一个 spec**，
而第一版只做了「搜索结果 → 导入」，没有能直接贴地址的地方——
`add` 那条最核心的入口被降级成了附属路径。

- 区段「按地址安装」：地址输入框 + 6 行格式示例（`owner/repo` / `#分支` / `/子目录` /

### 9b. 按钮密度收敛（两轮用户反馈）

用户两次指出「按钮太多 / 太丑」。两轮改的都是**同一件事：按钮密度**，
根因是我把「每个动作都配一个按钮」当成了「给每个动作一个入口」。

| 位置 | 改前 | 改后 | 依据 |
| --- | --- | --- | --- |
| 总览·远程卡头 | 4 个（检查更新 / 按地址安装 / 搜索导入 / 管理…） | **2 个**（检查更新 / 管理…） | 「按地址安装」「搜索导入」也都是去远程页，只是落在不同区段——摆四个按钮让整页密度失控 |
| 远程页·工具区 | 4 个（看内容… / ＋定义 / 检查更新 / 全部更新） | **2 个**（检查更新 / 全部更新） | 「在订阅源里看」是重复的（远程 hub 本身就是个订阅源，总览已有卡片）；「＋定义」是低频动作，挪进内容区标题行 |
| 远程页·按地址安装 | 6 个示例按钮 | **0 个按钮**（示例改成 `.spec-sample` 虚线 chip，点了填入） | 那 6 个是「写法参考」不是动作，摆成按钮凭空多 6 个 |

实测按钮数：总览 5（页头 3 + 卡片 2）· 远程内容段 7 · 远程按地址段 **2**。

「在订阅源里看…」与「查看内容」两个按钮一度并存——文案只差一个字、
位置相邻，是明确的误点陷阱，已让前者只在内容区段出现并改名为「在订阅源里看…」。

### 过程中修掉的真 bug

1. **`remoteContentsWithCells` 丢字段** —— 它重新打包时没带 `lastCheck`，面板永远拿不到
   「待更新」缓存（版本徽标不显示）。已修。
2. **`removed` 与 `unknown` 混淆** —— 上游完整扫过却找不到 = `removed`；
   只按台账路径查、路径又对不上 = `unknown`（不能说删了）。已按 `scanned` 标志区分。
3. **基准提前写回导致自我比对** —— 第一版把新算出的 `folderHash` 提前写进台账，
   再拿它跟上游比 —— 等于自己跟自己比，判定永远「最新」。改为**判定之后**才写。
4. **平台短名撞车** —— `shortLabel` 把 `workbuddy` / `workbuddy-ai` 压成同一个短名，
   列表里两行看着一样。改为直接显示平台 id。
5. **导入时克隆两次** —— 第一版为了拿指纹又克隆了一份上游。改为从已拉好的 staging 算。

### 环境备注（非代码问题）

本机 **git over https 到 github.com 被阻断**（`Connection was reset`），但 SSH 与
api.github.com 都通。远程检查因此走了 API 路径；clone 路径在 file:// 夹具上验证通过。
这不影响功能——两条路径算出的 tree SHA 完全相同。
