# 05 远程订阅第 2 轮：先看后导、台账无洞、UI 同投影

来源：loop-5 第 2 轮 subagent 调研（对标差距 + 文档缺口）。第 1 轮已完成的不再重复。

## 调研结论（本轮依据）

- **最大缺口 = add --list 对标**（参考 `skills/src/add.ts:1402-1443`）：nx-rh 的导入路径
  在 clone 落地前对内容全盲；`importToRemote`（remote-repo.js:86-92）其实已在 staging
  完成发现，「先列后导」只差停下来不拷贝。价值高、成本低。
- **最刺眼不一致 = submit 裸写**（transfer.js:223-238）：`--into` 指向远程订阅时通过
  订阅源校验（:251-256），`submitOne` 把实体拷进容器却**不写 `remoteRepo.skills`**——
  同一容器其余全部写方（import :117-123 / add :146-152 / link :172-179）都登记台账，
  删改还有 syncRemoteMeta（:283-298）兜底，唯独 submit 落入的条目显示为「手写定义、
  无上游」、update 永久 skip。
- **UI 投影分裂**（RemotePage.jsx:27-50,197-199）：自绘 `.row`，未用 shared.jsx:56 的
  SkillCard/skl-grid/useSel；条目不带 listAllSkills（queries.js:139-157）的 cells
  安装状态——同为 skill 列表，远程侧与本地侧是两套投影。
- **文档零覆盖**：README、CHANGELOG、assets/nx-rh 手册对远程订阅零提及；
  `skill hub cat` 尾部只提示 migrate，不告诉用户外部 skill 可以更新。

## 本轮需求

### 1. 先看后导（对标 add --list）
- `skill hub remote import <spec> --dry-run`：拉到 staging、列出将导入的 skill
  （名称/描述/版本指纹），**不拷贝**（与仓库既有 --dry-run 惯例一致）。
- Web「导入」确认弹窗：先取预览清单再确认（显示将导入哪几个，而不是只显示来源）。
- 验收：--dry-run 后磁盘无变化、无残留 staging；Web 确认前看得到清单。

### 2. 台账无洞（submit 落入远程订阅写元数据）
- `submitSkill` 的 into 命中远程订阅目录时，同步写 `remoteRepo.skills[name]`
  （spec 空 = 手写定义语义；本地改动属于用户，不挂上游）。
- 验收：submit --into <远程订阅> 后 `remote list` 认得出这条（manual，无上游），
  update 跳过它而不是失明。

### 3. UI 同投影
- RemotePage 内容列表换 `SkillCard` + `skl-grid` + `useSel`（与本地源同款），
  条目显示安装状态（cells）与上游/版本；详情可点进 `#/skills/skill/<name>`。
- 验收：远程订阅页与本地源页的卡片形态一致；勾选可用（为批量迁移铺路，
  批量迁移本身走 HubPage，不在此页重复）。

### 4. 文档与露出
- README「Skill 订阅与迁移」节补 `### 远程订阅`；CLI 命令总表补 remote 七行 + search。
- CHANGELOG `[Unreleased]` 补远程订阅条目（含 MIT 移植声明）。
- assets/nx-rh：SKILL.md 触发词与适用场景、references/skill-hub.md 补
  「远程订阅（外部 skill）」节与失败排查行（命令名逐一对照 action 声明，
  过 docs-commands 校验）。
- 露出：`skill hub cat` 尾部在来源是远程订阅时提示可 `remote update`；
  `skill hub sources` 空态提示 remote import。

## 明确不做（本轮外）
- `use`（不安装直接用）——agent 启动器职责，超出 hub 管理器形态（调研判定价值低）。
- plugin-manifest 清单、blob 快路径、skill-relocation 改名追踪——留待后续轮评估。
- remote remove 的 --all 互斥校验——小项，随下轮顺手。
