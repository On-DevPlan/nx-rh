# 04 远程订阅 = 一等订阅源：与本地 hub 同构

来源：loop-5 第 1 轮 subagent 深度调研（对标 `.claude/repo/skills` + 交互/信息架构审查）。
调研结论的核心：**远程订阅仓库「只能进，不能用」**——它数据面齐全，但信息面没接上；
再叠加三处真缺陷与命名/结构混乱。

## 调研证据（要点）

- **能力断层**：`Overview.jsx:54` 的 `s.remote ? goRemote() : goHub(s.path)` 把远程容器特判出
  HubPage，于是远程 skill 拿不到本地源已有的卡片网格、勾选批量迁移、详情跳转。
  CLI 侧 `migrate --all` 也只覆盖主源（`sources.js:69`），远程容器不在其中。
- **三处真缺陷**：
  1. `remote-hub.js:207` 写盘用 `remoteHubDir()`、读取用 `st.dir`（`:48`）——两者不一致时
     「更新完界面没变化」；
  2. `RemotePage.jsx:44` 的「加软链…」传已存在的名字，必然撞 `remote-hub.js:156` 的冲突；
     且语义错位（想做「链出去」，实现是「链进来」）；
  3. `remote-hub.js:100/131/156` 用上游 frontmatter 的 name 拼路径，未过 `assertSafeName`
     ——`name: ../../evil` 可写出容器目录之外。
- **元数据泄漏**：`purgeSkill`（`entity.js:152`）删掉远程容器里的实体却不清 `store.remoteHub.skills`，
  下次 `remote update` 会把它**从上游复活**；`dedupe` 把容器条目转成软链后同样失配。
- **命名混乱**：同一概念有 5 个词（远程订阅 / Hub / remote / 远程源 / 远程订阅源），
  死词 `远程源` 仍在用户可见文案里（`remote-hub.js:90,92`、`renders.js:298`）；
  死代码 `renders.js:294 renderSync`、`scan.js:100 snapshotSkills` 无 action 引用。
- **入口冗余**：`skill hub subscribe <远程规格>` 与 `skill hub remote import <远程规格>`
  100% 重叠；`remote add/list/update/remove` 与 `hub add/list/update/remove` 同动词反义
  （`update` 尤其危险：改写正文 vs 重拉上游）。
- **信息割裂**：`hubContents()` 有上游/版本无安装状态；`listAllSkills()` 有安装状态无上游。

## 本轮需求

### 1. 远程容器与本地源同构（核心）

- `Overview.jsx`：去掉远程特判，远程容器卡片与本地源卡片**同样**进 `#/skills/hub/<path>`；
  卡片上用「远程订阅」标签区分。
- **顶栏不留远程按钮**（调研 R6/A18）：总览页原来的「远程订阅…」按钮与订阅源卡片
  同目标、重复。收敛为：
  - 订阅源卡片主体 → 进 HubPage 看内容（同本地源）
  - 远程订阅卡片上的「管理…」按钮 → 进 `#/skills/remote` 做发现/导入/更新/定义
  - `#/skills/remote` 页头「看内容…」→ 回到 HubPage（两页互相可达）
- `HubPage`：远程容器的 skill 与本地源一样可勾选、批量迁移、点进详情。
- `migrate --all`：覆盖**全部订阅源**（不只主源）；`--source` 支持短标识
  （能指名「远程订阅那份」），blocked 文案把远程容器标出来。
- `skillInfo`（详情）：远程 skill 多一段「上游」信息（spec / ref / 版本指纹 / 导入与更新时间）。

### 2. 修三处真缺陷 + 元数据同步

- 更新写盘统一用 `st.dir`（与读取同源）。
- 上游 name 一律过 `assertSafeName`（导入 / 添加定义 / 加软链三处）。
- `purge` / `remove` / `dedupe` 命中远程容器条目时，同步 `store.remoteHub.skills`
  （删除 → 删元数据；转链接 → 清 spec），杜绝「复活」与状态横跳。
- 「加软链」拆成两个语义正确的动作：**链出**（把容器里这份链到别处）与**链入**（别处链进容器）。

### 3. 命名与结构收敛

- 概念二统一叫「远程订阅」，代码标识符统一 `remote*`：
  `remote-hub.js` → `remote-repo.js`，`ensureHub→ensureRemote`、`hubContents→remoteContents`、
  `importToHub→importToRemote`、`addHubDefinition→addRemoteDefinition`、
  `linkIntoHub→linkIntoRemote`、`updateHub→updateRemote`、`removeFromHub→removeFromRemote`、
  `remoteHubDir→remoteRepoDir`、`store.remoteHub→store.remoteRepo`。
- 清死词与死代码：`远程源` → 「上游」；删 `renderSync`、`snapshotSkills`；
  `store.remoteSources` 字段与其清理分支一并删（旧模型已在 0.18 作废）。
- 消除双路径：`skill hub subscribe` 只管本地目录；远程规格一律 `skill hub remote import`。
  相应修 `renders.js:327` 的提示文案。

### 4. 列表信息合流

`remoteContents()` 每项补安装状态（cells），`listAllSkills()` 每行补上游信息
（spec/ref/hash）——`skill hub list` 与 `skill hub remote list` 成为同一份数据的两个投影。

## 明确不做（本轮外）

- 参考实现的 `add --list`（先列后装）与 `use`（不安装直接用）——留给后续轮。
- 远程侧**不**做「直接装到平台目录」（与本项目形态的有意差异）。
- README 与 assets 手册的文档补全——留给后续轮（调研确认 README 对远程子系统零文档）。

## 验收

- [ ] 远程容器卡片进 HubPage，远程 skill 可勾选、批量迁移、进详情
- [ ] `migrate --all` 覆盖全部订阅源；`--source` 能指名远程那份
- [ ] 详情页显示上游信息（spec / ref / 指纹 / 更新时间）
- [ ] purge / remove / dedupe 后 `remote update` 不会把已删 skill 复活
- [ ] 上游 `name: ../..` 被拒（INVALID_INPUT），不写到容器外
- [ ] 更新后目录与列表一致（st.dir 同源）
- [ ] 代码里不再有「远程源」这个死词，也没有 Hub/remote 混用
- [ ] `pnpm test` 全绿（lint + build + smoke + unit）
