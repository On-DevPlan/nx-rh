> 目标（用户原话归纳）：Web 里订阅源列表的「远程订阅 Hub」卡片固定显示在最后一个；

> **先出几版 HTML 原型供审核，审核通过后才动 src/ 生产代码。**

> 本文件每轮追加小节（R1 / R2 / R3），不覆盖旧内容。原型在 `temp/proto/*.html`，

`svc/remote*.js`、前端注册表（报告要点摘录如下）。

**已完成、不用再做的：**

| 用户目标 | 现状 |
| --- | --- |
| a. 远程卡固定最后 | **后端已实现**：`svc/sources.js:38` 一行排序 `Number(!!a.remote) - Number(!!b.remote)`，任意登记序下远程源恒排末位 |
| b. 远程控制独立页 | **页面已存在**：`#/skills/remote`（`RemotePage.jsx`，模块内 hash 子路由），已有内容列表（含逐条更新/加软链/移除）、发现导入（先 dry-run 预览再导）、全部更新、＋添加定义 |
| c. 与其他页同构 | 骨架已同构：Crumbs + sub-head + skl-grid + CliHints；**细节漂移 8 处**（见下） |

**端点齐全、Web 未暴露的 flag / 入口（缺口清单）：**

- `remote link-out`（POST /api/skills/remote/link-out）——**无任何 Web 入口**
- `remote update --prune`（清理上游已删僵尸）——Web 无开关
- `skill hub refresh`（快照比对）——无按钮，只在 CliHints 折叠列表里
- `remote import --name`（只导一个）——Web 未暴露
- `remote remove` 后端支持批量数组——Web 只用了单个
- `search --limit`——Web 无下拉

**UI/UX 差距（对照其他页，8 处）：**

1. 破坏性操作样式漂移：移除用 `sc-mini` + inline 红色，全局惯例是 `btn danger`
2. 确认机制不对等：远程移除一次性确认，没有「彻底删除」那套 dry-run 预演 + 二次闸门
3. 表单交互原始：加软链/添加定义是串行两次单字段 dialog，无校验、无 content；其他页复杂表单用 Modal 组件
4. 「发现」结果是裸 `.list`，没有 `.card` 容器（ProjectPage 同类列表有）
5. 全选无半选态（HubPage 有 `indeterminate` 处理）
6. **勾选是死功能**：checkbox 写共享 `ui.selSkills`，但页内没有任何批量动作按钮——勾了没出口
7. 错误态薄弱：加载失败丢 `e.message`，只显示「读取失败」
8. sub-meta 细节漂移：硬编码兜底路径 + 类名与 PlatformPage 不一致

**版本管理的数据边界：**

- 台账只存**最新 hash**；`from → hash` 的旧指纹只在单次 update 响应里出现、不落盘
- 即「版本历史 / 回滚」没有数据模型，要做需台账加 `history: [{hash, updatedAt}]`，
  且 `importToRemote / updateRemote / addRemoteDefinition / upsertRemoteSubmitMeta`
  四个写点同步——**增量最大，标记为后置提案**

1. 远程卡位置：两版都放订阅源列表**最末**；v1 在「＋订阅新目录」tile 之后（绝对最后），

3. 「同步中心」把「检查 → 出计划 → 勾选应用」做成显式三步（对应 `refresh` + dry-run 意识 +

4. 版本历史/回滚是**唯一需要后端改数据模型**的提案（B7），原型里已标注；不做也不影响其余项。

## R2（loop-6 第 2 轮）

### 0. 过程发现：轮次语义与「强制三轮」

`nx-rp loop` 的 iteration **从布防回合起算**（`loop start` 即 iteration=1），而布防回合
只做了布防不干活——按默认语义，3 轮上限实际只给 2 个工作回合。已 `loop update
--id loop-1 --maxIterations 4` 补足，保证 R1/R2/R3 三个真实工作轮。
**这条值得回灌 rp-loop skill 文档**（布防轮计数的坑），待循环结束后处理。

### 1. R2 已落地的保真度修复（评审报告回来前先修的确定项）

- **导入预演多技能化**：真实 `remote import <spec>` 不带 `--name` 时导入仓库全部 skill
  （dry-run 返回 `skills[]` 数组），R1 两版原型的预演弹窗都写成了单 skill。v1/v2 的
  导入弹窗已改为：dry-run 实测 N 个 skill 的清单 + 逐条勾选（全不勾 = 全部导入，
  勾选子集 = 等价 `--name`），弹窗标题改为按规格（owner/repo）而非单个 skill 名。

（R2 评审结论与后续迭代见下——评审 subagent 报告到达后补全。）

### 2. R2 评审结论：R1 原型的保真度错误（Explore subagent 对照真实实现核实）

**凭空虚构的能力（最大问题，两版都犯）：**

| 虚构项 | 真实情况 |
| --- | --- |
| 台账「状态」列（最新/待更新） | `remoteContentsWithCells` **没有任何与上游比对的状态字段**；比对只发生在 `updateRemote` 里，且它边检查边换盘（hash 不同直接替换），**没有 check-only 模式**。「1 待更新」徽标、「检查更新」按钮、「同步中心」的「先出计划再应用」都建立在不存在的能力上 |
| 行级 diff（SKILL.md ±32 行） | update 只返回 hash；staging 拉完即删，**无任何 API 能产出内容 diff** |
| 更新预演（只看不改） | 不存在；`updateAll` 是边检查边更新，跑完 toast「已检查 N 个，M 个有更新」 |
| 搜索结果的「描述」列 | 注册表 API 只返回 `{name, slug, source, installs}` 四个字段，**无描述**；owner 是自由文本输入框不是下拉 |

**格式/字段失真：**

- 指纹 tag 真实格式是 `↑仓库尾段@hash前6`（如 `↑skills@a3f9c1`）装在 `.tag` 里；原型画成裸 8 位 mono 文本
- 手写/链入条目在真实 RepoRow **不显示指纹**（原型画了）
- dry-run 弹窗里指纹**已经算好**（staging 算完才返回），原型写「下载后计算」是错的
- 「现存软链（出去方向）」**无数据源**（linkFromRemote 不登记台账）；「链入对端路径」不在 remoteContents 投影里
- 总览卡次序：实现语义是 **sources 组内垫底**（add-tile 仍全网格最后）；R1 把远程卡画到 add-tile 之后是提案不是现状

**同构细节：** `.tag.upd` 不是 style.css 既有类；原型「定义与软链」卡用了 `.row/.name/.desc` 但没带样式；弹窗宽应统一 720px；台账表格 vs 真实页 skl-grid 卡片是布局换新，需显式声明为新约定。

### 3. R2 修订（两版按差异轴分别修，不收敛成同一张图）

**v1 保守版 = 「现状数据能支撑的样子」（整体重写）：**

- 删「状态」列与「待更新」概念 → 列改为：形态 / 指纹（`↑repo@hash6` tag）/ 安装（`已安装 n/m`）/ 更新于（相对时间）——对齐真实 RepoRow 的信息密度
- 「检查更新」更名「全部更新」，行为 = 现状（边检查边换盘），toast 汇总
- 删更新预演弹窗与 diff；指纹列手写/链入行显示「—」
- 搜索区删描述列、owner 改文本框；导入预演 = dry-run 多选清单 + **已算好的指纹**
- 操作列对齐现状三键：更新 / 加软链… / 移除（danger）；详情弹窗（spec/指纹/时间+Copyable）与迁移弹窗（MigrateToDialog 同构）保留并标注
- 新增「状态机样例」折叠区：空容器引导 / 忙碌态（防重复触发）/ 搜索失败 toast / 部分失败汇总（含 --prune 后续入口）
- 同构收尾：删自造 `.tag.upd`、补 `.row` 系样式、弹窗 720px、页脚声明「台账表格是本页新约定」、总览卡次序回归现状（远程卡组内垫底）

**v2 工作台版 = 「保留骨架，越界能力全部显式标注增量提案」：**

- 新增 `.tag.prop`（虚线边框）标记：待更新徽标、同步中心整块、行级 diff、现存软链表、
  远程卡绝对最后的位置提案——每处注明需后端补什么（check-only 比对、缓存上次结果、
  替换前留旧副本、link-out 登记、对端路径投影）
- 指纹 tag 对齐 `↑repo@hash6`；statline 口径定死（「4 个 skill 已安装」按 skill 计）
- 搜索区对齐真实字段（删描述列、owner 文本框、注明四字段返回）；m-update-all 删掉不存在的「预演清单」复选；「更新此来源」注明实现要按该来源全部 name 循环
- 高级区补同一套「状态机样例」（部分失败含「上游已删除」分支 + prune 入口）
- 同构收尾同 v1（弹窗 720px、页脚声明新约定与位置提案）

**两版共同的 R2 新增：** 导入预演多技能化（R2 §1）、真迁移弹窗（MigrateToDialog 同构：平台复选 + 形态）、
批量更新结果弹窗（per-name status：已更新/无变更/跳过/失败，对应真实返回数组；error 条目 name 装 spec 的后端 quirk 已记录）。
