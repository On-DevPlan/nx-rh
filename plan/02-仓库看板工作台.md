# 02 仓库工作台：主题看板 + 手机式仓库卡片（P1）

来源：KV 任务「优化仓库管理——仓库是小方格卡片（类似手机 app）；多项目编排层参考
skill 的 UI（顶部主题容器、下面是仓库）；支持拖拽（看板式操作）；可导入专业看板
（一个看板 = 一个主题，纵向显示）；支持 CLI 快速判断看板里的 repo 和 desc」。

## 现状

仓库页是一张登记表（table：名称/路径/标签/时间/操作），全部仓库平铺一列，
没有分组与编排概念；CLI 只有 repo.* 六条（登记 CRUD + 扫描 + 打开）。
skill 域已有「订阅源卡片 + 内容区」的容器式版面（skl-card / colhead）可参照。

## 处理意图

**一个看板 = 一个主题容器，纵向堆叠；仓库 = 容器里的方格卡片。**

- 数据：store 增 `boards: [{id, name, desc, createdAt, repoIds: []}]`——成员关系
  挂在看板上（repoIds 有序），不在任何看板里的仓库落「未分组」；repo 登记删除时
  从看板里同步摘除；删除看板 = 卡片全部回到未分组（登记本身不动）。
- 视图：每个看板一张纵向 section（头部：主题名 + 描述 + 计数 + 重命名/删除；
  下方 repo 方格网格）；未分组 section 固定在最后。方格卡片 = 手机 app 风：
  首字圆角块 + 名称加粗截断 + 描述两行截断，hover 浮出 打开/编辑/删除。
- 拖拽：卡片可拖（HTML5 DnD，与代码库其余拖拽同一套）——拖到看板空白 = 追加到
  该看板末尾；拖到某张卡片上 = 插到它前面；拖回未分组 = 摘出。落点高亮。
- 导入 / 导出：导入收一段 JSON（`{boards:[{name, desc?, repos:[{path|name, desc?}]}]}`），
  一个导入的看板 = 一个新主题；条目按 path（大小写不敏感）或 name 匹配已登记仓库，
  匹配不上的不硬造登记、如实报告。导出输出同一结构的 JSON（面板复制 / CLI 直出）。
- CLI（用户要的「快速判断看板里的 repo 和 desc」）：`board list` 按主题列出
  仓库名 + 一句话描述；`board add/get/update/remove/assign/import/export` 与面板同源。
  动作声明补 `resource: 'board'` 五端完备（registry 一致性测试会盯）。

## 改动

- `core/store.js`：EMPTY/normalize 增 `boards`。
- `modules/repos/boards.js`（新）：看板 service（纯 store 事务，无传输层概念）。
- `modules/repos/service.js`：removeRepo 摘除看板成员。
- `modules/repos/index.js`：board.* 八条 action（CRUD 五条 + assign/import/export）。
- `modules/repos/view.jsx`：工作台版面（看板 sections + 方格卡片 + 拖拽 + 四个弹窗入口）。
- `web/frontend/style.css`：bd-* 样式（主题容器 / 方格 / 落点高亮 / 窄屏降级）。
- `tests/unit/boards.test.mjs`（新）：建/改/删/移/导入/导出/删除联动。
